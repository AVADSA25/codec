# P2.2 — Rename, pin, archive, group, load more and export chats

Item 3 of docs/UI-PHASE2-3-PLAN.md. Builds on the P2.1 sidebar (static/codec-shell.js).

## Why

The sidebar lists the 30 newest chats and nothing else: no way to rename, pin, archive, export or find an
older chat without search, and deleting is one chat at a time through a native confirm. Saving is
append-only: a regenerated or edited turn leaves the discarded reply in qchat.db, and it comes back on
reload, above the new one.

## What

### Server (routes/qchat.py)

- **Additive schema, backup first.** `qchat_sessions` gains `pinned INTEGER DEFAULT 0` and
  `archived INTEGER DEFAULT 0`; `qchat_messages` gains `superseded_at TEXT` (NULL = current). Before the
  first `ALTER TABLE` that adds them, the connection copies the database with SQLite's online backup API to
  `~/.codec/qchat.db.bak-p2.2` (0600), once. No row or column is ever deleted by this change.
- **List with paging.** `GET /api/qchat/sessions?offset=0&limit=30&archived=0` returns pinned chats first,
  then by `updated_at`, with `pinned`, `archived` and `created_at` on each row. `limit` is capped at 100.
  The old call (no parameters) returns what it returned before, minus archived chats.
- **Rename, pin, archive.** `PATCH /api/qchat/session/{sid}` with any of `{"title": str, "pinned": bool,
  "archived": bool}`; 404 for an unknown chat; a title is trimmed to 60 characters and may not be empty.
- **Export.** `GET /api/qchat/session/{sid}/export?format=md|json` downloads the chat (current messages only)
  as Markdown (`# Title`, then `**You**` / `**CODEC**` with times) or JSON (`id`, `title`, `created_at`,
  `updated_at`, `messages`), with a `Content-Disposition: attachment` file name made from the title.
- **Replace-or-mark saving.** `POST /api/qchat/save` accepts an optional `discard_from` (an ordinal among
  the chat's current messages). The server marks every current message from that position on as
  superseded (sets `superseded_at`), then appends the new messages. Without `discard_from` it appends as
  before. Reading a chat, chat search, memory search (route and skill) and exporting skip superseded
  messages.
- **Save to Google Doc** (optional in the plan): `POST /api/qchat/session/{sid}/gdoc` exports the chat as
  text and creates a doc through the google_docs skill's new `create_doc(title, content)` helper (the
  skill's own create path keeps working; the skill manifest is regenerated). It creates a doc only on an
  explicit click.

### Chat page (codec_chat.html)

- Every message in `chatHist` carries its ordinal among the saved messages (`_row`), set on load and on
  each save. Regenerate and edit, which already drop messages from `chatHist`, remember the lowest `_row`
  they dropped; the next save sends it as `discard_from`. So a reload shows exactly what the page showed.
- After a save, a rename or a delete, the sidebar refreshes (P2.1 hook).

### Sidebar (static/codec-shell.js, codec.css)

- **Groups:** Pinned, then Today, Yesterday, Previous 7 days, Older, by `updated_at` (labels 12/600
  text-dim, as the brief says).
- **Row menu:** a three-dot button on hover (always shown on touch screens) opens a menu: Rename (inline
  edit in the row, Enter saves, Esc cancels), Pin / Unpin, Archive / Unarchive, Export as Markdown, Export as
  JSON, Save to Google Doc, Delete.
- **Load more:** scrolling near the end of the list loads the next 30 (offset paging), until a short page.
- **Archived view:** an "Archived chats" row at the end of the list switches to the archived list, with a
  back row; archived chats unarchive from their menu.
- **Select mode:** a "Select" action in the list header shows a check box on each row and a bar with
  "Delete N" and Cancel; Delete asks in the bar itself ("Delete 3 chats? Delete / Cancel"), no native
  dialog. Single delete from the row menu uses the same in-page confirm on the row.
- No public share links.

## Not in this item

Versions of regenerated answers and thumbs (P2.7, which uses `discard_from`); the styled menu component
shared by every picker (P2.6, which can adopt the row menu); temporary chats (P2.11).

## API or schema change

Three additive columns; `GET /api/qchat/sessions` gains `offset`, `limit`, `archived` and three fields per
row; new `PATCH /api/qchat/session/{sid}`, `GET /api/qchat/session/{sid}/export`,
`POST /api/qchat/session/{sid}/gdoc`; `POST /api/qchat/save` gains `discard_from`.

## Test plan

tests/test_qchat_history.py, against a temp qchat.db:
- migration adds the columns once and writes the backup once; existing rows keep their data;
- list: pinned first, archived hidden by default and listed with `archived=1`, offset paging;
- PATCH rename / pin / archive, 404, empty title refused;
- export Markdown and JSON, attachment name, superseded messages left out;
- save with `discard_from` marks the tail and appends; reading and search skip superseded rows;
- the Google Doc route calls `create_doc` with the exported text (skill mocked).
Static checks on the page and the shell: `discard_from` sent from regenerate and edit, groups, menu items,
load more, archived view, select mode with in-page confirm, no `confirm(` left in the shell.
Browser: rename, pin, archive, export download, load more with 70 made-up chats, select-delete, regenerate
then reload shows one answer.

## Rollback

Revert the PR. The new columns and the backup stay (additive); old code ignores them, and superseded rows
reappear on reload as before.

# P3.6 — Skills page: browse, try, check readiness

Item 24 of docs/UI-PHASE2-3-PLAN.md. Stacked on P3.4 (#432).

## Why

There is no place to see what CODEC can do. Cortex's Skills Registry is a bare name list, Settings has a separate
Voice Triggers list, and Skill Reviews sits alone in Home's Skills tab. Nothing says where a skill works (Chat, the
voice call, Claude over MCP) or why it fails (Google not connected, a missing permission). `/skills disable` writes a
list that nothing reads, so a skill cannot really be turned off.

## What

Home's **Skills** tab becomes the Skills page:

- Every registered skill, grouped like the '@' picker (Google, Browser, Mac, Memory and notes, Reports, Home and
  media, Tools, Other), with its description, its trigger phrases and a search box.
- **Where it works**: Chat (the chat allowlist), Voice (every skill except the voice call's skip list), Claude over
  MCP (exposed and not blocked over HTTP; "asks you first" for the consent list).
- **Readiness**: Ready; Limited (it works, with less: web search without a Serper key falls back to DuckDuckGo,
  Google Docs without a Pexels key gets no stock images); Needs setup (Google skills without a Google sign-in, with
  a link to Connections; screenshot reading without Screen Recording; Accessibility control without Accessibility).
  The two macOS permissions are read without a prompt (`CGPreflightScreenCaptureAccess`, `AXIsProcessTrusted`) and
  are the dashboard's own, which runs Chat's skills; the page says so.
- **Try it**: opens Chat with the skill picked (the P2.3 '@' chip), for skills Chat can run.
- **Triggers**: the Voice Triggers editor moves here, per skill (same Save and Reset as before). Settings keeps the
  keyboard shortcuts and points to Skills.
- **Skill reviews** stay at the top of the page.
- **On/off switch**, now enforced. `config.json:skills_off` lists the skills the owner turned off (a deny list, so a
  new skill is on until turned off; the old `skills` list that nothing read is ignored, since honouring it would turn
  off every skill added after it was written). Every path checks it before running a skill: `codec_dispatch`
  (`check_skill` skips it, `run_skill` refuses it: wake word, chat, sessions, bridges, agent runner), the MCP tools,
  the voice call's matcher, crew tools, and the '@' list. `/skills enable|disable` writes the same list. A change is
  one value-free `skill_switched` audit line. Processes read the file again when it changes (no restart for the
  switch itself; the new code needs the usual restarts at deploy: dashboard, open-codec, and the owner's
  codec-mcp-http and codec-agent-runner).

The read-only `health_check`, `backup_status`, `audit_report` and `memory_history` join the chat allowlist.

## API

- `GET /api/skills/catalog` → `{skills: [{name, label, description, group, triggers, customized, paths: {chat, voice,
  mcp, mcp_asks}, ready: ready|limited|setup, reason, on}], groups, permissions_note}`.
- `PUT /api/skills/switch` `{name, on}` → `{name, on}`.

No change to skill files, the manifest, memory.db or the security lists (`_HTTP_BLOCKED`, `_HTTP_ONLY_BLOCKED`,
`_HTTP_CONSENT_REQUIRED`). The chat allowlist only grows by four read-only skills, as this plan says.

# P2.7 — Keep regenerated versions and add thumbs feedback

Item 16 of docs/UI-PHASE2-3-PLAN.md.

## Why

Regenerate throws the previous answer away, and editing a question throws away the old question and everything
after it. There is no way to go back to an answer that was better. There is also no way to tell CODEC a reply was
wrong or too long, so neither the shift report nor the self-improvement run ever hear about bad replies.

## What

**Versions (Chat page).** Regenerate and edit no longer destroy the turn they replace. The replaced part of the chat
(the answer for regenerate; the question and everything after it for edit) is kept as an earlier version of the same
turn. The first message of each version shows a small pager, `‹ 2 / 3 ›`, in its action row. Going to another
version swaps the tail of the chat back in, exactly as it was (including later versions nested inside it).

- Only the version on screen is in `chatHist` (what the model sees) and in the saved chat. Switching version marks
  the saved rows from that turn on as superseded (the P2.2 `discard_from` mechanism) and saves the chosen version's
  rows, so a reload shows what the page showed. Nothing is deleted.
- The page keeps a mirror of the saved rows (`_savedRows`) next to `chatHist`, so a version is re-saved with the
  text that was saved (a message with attached files saves its short form, not the file text sent to the model).
- Versions live on the page. After a reload only the selected version is shown; earlier versions stay in qchat.db as
  superseded rows but are not browsable (no new column for that).
- Regenerate works on the trailing answer(s). If a regenerate produces nothing, the previous version comes back.
- The pager is disabled while a reply is streaming.

**Thumbs feedback.** Every CODEC reply gets thumbs up and thumbs down in its action row (`aria-pressed`). Thumbs
down shows three optional reason chips under the reply: "Wrong", "Too long", "Didn't use my data". Clicking the
pressed thumb again clears the rating.

- `POST /api/qchat/feedback` `{session_id, content, rating: "up"|"down"|"none", reason, model, skill}` stores one row
  per reply in a new `qchat_feedback` table in `~/.codec/qchat.db`, keyed by the chat and a SHA-256 of the reply
  text (the reply text itself is not copied; its length is). A change of mind updates the row; "none" sets
  rating 0, the row is never deleted.
- It emits one `chat_feedback` audit event, metadata only: rating, reason, model, skill, reply length. No text.
- **Shift report** section 1 gains a "Reply feedback" line: ups, downs and the top reasons, from `chat_feedback`
  events in the window.
- **Self-improvement** input: `_find_gaps` adds a `disliked_tool` gap for a skill with 3 or more thumbs-down on the
  day (the skill that produced the reply, when there was one), so the nightly run can draft an improvement proposal
  for it. Proposals stay draft-only, as today.

**More menu.** A reply's three-dot button opens a small menu (a new generic `CodecShell.actions(button, items)`
popover with the history menu's look and keyboard handling):

- "Retry with Think": turns Think on (`toggleThinking`) and regenerates.
- "Retry with another model": opens the model picker (`CodecShell.menu(modelSelect).open()`); when the switch
  finishes, the reply is regenerated with the new model. Closing the picker without a change cancels it.

## API or schema change

- New table `qchat_feedback (id, session_id, msg_hash, rating, reason, model, skill, chars, created_at,
  updated_at, UNIQUE(session_id, msg_hash))`. Additive; created after a one-time backup copy
  `qchat.db.bak-p2.7` (owner-only) when the table is missing and the database has rows.
- New route `POST /api/qchat/feedback`; new audit event name `chat_feedback` (the envelope is unchanged).
- `CodecShell.actions(btn, items)`; `CodecShell.menu(select)` gains nothing (its `open()` exists).

## Test plan

tests/test_chat_versions_feedback.py:
- Route: up, down with a reason, change of mind, "none" keeps the row with rating 0; bad rating and missing chat
  refused; the reply text is not stored; the audit event carries no text; the backup is made once before the table
  is added to a database with rows, and not for an empty one.
- Shift report: the feedback line counts ups, downs and reasons; no line without events.
- Self-improve: 3 thumbs-down on a skill make a `disliked_tool` gap; 2 do not; feedback events do not count as tool
  calls for the error-rate gap.
- Page: regenerate and edit keep versions (`_verKeep`), the pager and its swap (`_verShow`) re-save through
  `discard_from`, thumbs and reasons post to the route, the more menu offers both retries, the shell exports
  `actions`. Under jsdom (skipped without it): the swap puts the old tail back and restores `chatHist`.

Negative control: the new tests fail on the base commit.

Browser (on the Mac, throwaway dashboard): regenerate twice and browse 1/3..3/3, reload shows the chosen one; edit a
question and browse back; thumbs and reasons; both retries; 1470x956, 375x812, light theme; no console errors.

## Rollback

Revert the PR. The `qchat_feedback` table stays (harmless, unread); `qchat.db.bak-p2.7` can be deleted by hand.

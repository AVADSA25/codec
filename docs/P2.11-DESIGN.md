# P2.11 — Temporary chat that is not saved to history or memory

Item 18 of docs/UI-PHASE2-3-PLAN.md.

## Why

Every chat is saved to the history (qchat.db) and can feed memory: replies recall past conversations and open
threads, the observer summary goes into the prompt, and skills such as `fact_extract` or `standing_rules` save what
was said. There is no way to ask something once and leave nothing behind.

## What

**Page (Chat).** "Temporary chat" in the + menu (a checkbox item, like "Search the web"). Turning it on or off starts
a fresh chat. While it is on:

- an eye-off "Temporary" chip sits in the composer bar (its x turns it off) and the composer border is dashed;
- the empty chat says "Temporary chat: not saved to history or memory. The audit log still records what CODEC
  does." The label never says "no trace", because the audit log still records events;
- `saveMessages` returns at once, so nothing reaches `/api/qchat/save` and the chat never appears in the sidebar;
- every `/api/chat` call (send and regenerate) sends `temporary: true`;
- thumbs up / down (P2.7) are hidden: a rating needs a saved chat;
- opening a saved chat from the sidebar leaves temporary mode. A reload also leaves it (the toggle is not stored).

**Server (`routes/chat.py`).** With `temporary: true` the turn:

- skips memory recall in `_enrich_messages` (voice, chat and vibe history); links and web search still work;
- skips the open-threads block (Daybreak) and the observer summary in `_build_chat_system_prompt`; the operator's
  standing rules still apply (they are instructions, not recall);
- never runs the memory-writing skills `auto_memorize`, `fact_extract`, `thread_note`, `standing_rules`,
  `memory_save` on any chat path: a trigger match, an '@' pick or a post-LLM `[SKILL:...]` tag. The reply says
  "Not saved: this is a temporary chat, so nothing goes to memory. Turn off Temporary chat in the + menu to save it."

Agents and Project mode keep their own records (crew jobs, project folders) as today; only the chat transcript is
not saved. The vision call from Chat sends no session id, so it saves nothing either.

## API or schema change

`POST /api/chat` accepts `temporary` (bool, default false). No schema change.

## Test plan

tests/test_temporary_chat.py: `TEMPORARY_NO_MEMORY_SKILLS` holds the five skills; each of the three skill paths
refuses them when temporary and runs them otherwise (run_skill stubbed); `_enrich_messages` recalls no memory when
temporary (memory stubbed) but still fetches a link; the system prompt has no observer summary or open threads when
temporary and keeps standing rules; `/api/chat` passes the flag through to all of them; the page has the toggle,
chip, dashed border, honest label, the save skip, the flag on both `/api/chat` calls, and leaves temporary mode when
a saved chat opens.

Negative control: the new tests fail on the base commit.

Browser (on the Mac): toggle on, chat, reload: nothing in the sidebar; "remember that I like tea" answers with the
refusal; 1470x956, 375x812, light theme; no console errors.

## Rollback

Revert the PR. Nothing is stored by this feature.

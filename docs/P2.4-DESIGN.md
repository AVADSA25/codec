# P2.4 — Memory page: see, correct and forget what CODEC remembers

Item 14 of docs/UI-PHASE2-3-PLAN.md.

## Why

CODEC keeps several kinds of memory, and none of them has a page: dated facts (the `facts` table), Daybreak's
working threads, standing rules, the "about me" text (`~/.codec/memory/identity.txt`), and the conversation log in
`memory.db`. The `/api/memory/*` routes (search, rebuild) have no caller. The only way to correct or forget
something is to ask in chat and hope a skill matches.

## What

A **Memory** section in Settings (Home, Settings, Memory; `/#memory`), next to General, Connectors and Audit.

- **Facts** (`query_valid_facts`, threads left out): each fact with its value, type and date. **Edit** writes a new
  value with `store_fact(..., supersede=True)`, so the old one stays in the history. **Forget** closes it with
  `expire_fact` (nothing is deleted). **History** lists every version (`get_fact_history`).
- **Working threads** (Daybreak): the open threads with **Close**, through the existing
  `POST /api/today/threads/done` (`codec_daybreak.close_thread`).
- **Standing rules** (`codec_standing_rules`): the list with how often each reached the model, **Add**, **Remove**,
  **Clear all** (asks first). The same limits as the skill (25 rules, 500 characters each).
- **About me**: a text box for `identity.txt`, which voice and the wake word read at the start of each
  conversation (chat does not use it). Up to 1,500 characters, written atomically and owner-only (0600).
- **Search**: a search box over `memory.db` (`GET /api/memory/search`) and **Rebuild index**
  (`POST /api/memory/rebuild`).
- **Two switches** (`config.json:memory`):
  - **Save facts from text** (`fact_extract`, default on). Off: the `fact_extract` skill saves nothing, on every
    path (chat, voice, MCP, and the nightly run below, which uses it), and says why.
  - **Learn from each day's chats** (`auto_memorize`, default off). On: a managed schedule job
    (`sched_auto_memorize`, every day at 03:30) runs the skill, which reads the last 24 hours and saves the lasting
    facts through `fact_extract`. The job shows in Tasks, Schedules, with "Set up in Settings". It delivers nothing
    (a new internal delivery, `silent`: the run history only).
- **System prompts**: a link to the existing editor in Settings, General, not a second copy.
- **"Memory used" on replies**: `_enrich_messages` fills an optional `meta` dict with what it injected (past or
  recent chat, voice and Vibe lines, by count), the system prompt builder adds the standing rules and open threads
  it sent. `/api/chat` sends it as a `memory` event (stream) or field (JSON). A reply that used memory gets a small
  "Memory used" button: it lists the sources and counts and links to the Memory page.
- **Audit**: every change from the page is one `memory_changed` event, metadata only (the action, the fact key or
  rule id, lengths, counts; never a value).

## API or schema change

New: `GET /api/memory/facts`, `PUT /api/memory/facts` (edit), `POST /api/memory/facts/forget`,
`GET /api/memory/facts/history`, `GET/POST /api/memory/rules`, `DELETE /api/memory/rules/{id}`,
`POST /api/memory/rules/clear`, `GET/PUT /api/memory/about`, `GET/PUT /api/memory/settings`. Config key `memory`
(`fact_extract`). Schedule delivery `silent`. Audit event `memory_changed`. `/api/chat` adds `memory`. No database
change: facts are only superseded or closed, as today.

## Test plan

the history; forget closes; history; rules add, limits, remove, clear; about me cap and 0600; settings: the
`fact_extract` switch stops the skill and the nightly switch creates and switches off the managed job with
`silent` delivery; the scheduler delivers nothing for `silent`; `_enrich_messages` reports what it injected;
`/api/chat` passes `memory`; every change is audited without values; the Home page and chat page wiring.

Browser (throwaway dashboard): the Memory section's facts (edit, history, forget), threads, rules, about me,
search, rebuild, the two switches; a reply with "Memory used"; 1470x956, 375x812, light theme.

## Rollback

Revert the PR. Facts edited or forgotten stay as written (superseded or closed rows, as the chat skills leave
them); the `memory` config key and the managed job would then be ignored (switch the job off first).

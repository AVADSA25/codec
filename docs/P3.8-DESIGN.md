# P3.8 — Activity board for projects and background jobs

Item 26 of docs/UI-PHASE2-3-PLAN.md. Stacked on P3.7 (#434).

## Why

Project-mode agents (Phase 3 Steps 8-10) only show as small pills above Chat's composer, and only while they are
active: a finished or stopped project, its checkpoints, its files and its last message are nowhere. Crew runs live in
the dashboard's memory (`_agent_jobs`) and vanish when it restarts (a known gap in AGENTS.md §3). The cross-agent
permission list (`/api/agent_global_grants`) has no page. Two smaller gaps were logged for this item: deleting a saved
custom agent does not ask first, and a crew that needs no text (Daily Briefing, Email Handler) cannot start from an
empty Chat box.

## What

**Activity tab in Tasks** (`/tasks#activity`), refreshed every 5 seconds while it shows:

- **Projects**: every Project-mode agent, active ones first. Each row: title, status in words, an *n of N
  checkpoints* bar, elapsed time, the last message, and the actions that fit its state: Pause (running), Resume
  (paused), Extend budget (paused because its step budget ran out; asks how many steps, 1-100), Approve and Revise
  plan (awaiting approval; Revise edits the goal and each checkpoint's title and description, then the plan goes back
  for approval), Open the Inbox (blocked), Stop (any live state; asks first), Silence or Unsilence notifications,
  and Files (lists what it produced; on the Mac, Open folder).
- **Crew runs**: the crew jobs, newest first, with status, start time, duration, steps and the last progress line;
  Stop for a running one.
- **Permissions for every project**: the global allowlist by kind (sites, folders it may read, folders it may write,
  skills), each with Remove, and Add (kind and value). A folder value goes through the same refusal as a per-agent
  grant (traversal, blocklisted or over-broad paths are refused).

**Crew runs survive a restart.** `_agent_jobs` is written to `~/.codec/agent_jobs.json` (0600, atomic; the newest 50,
the last 50 progress lines each) when a run starts, ends or is stopped, and read back on first use. A run that was
still running when the dashboard stopped comes back as *interrupted*. New `GET /api/agents/jobs`.

**`GET /api/agents` gains progress fields**: `checkpoints_total`, `checkpoint_index`, `elapsed_s`, `status_reason`,
`can_extend`, `silenced`, `last_message` ({type, title, ts}). The existing fields stay.

**Chat's pills become the running-task rail** above the composer: one row per active project or running crew run,
with a small progress bar, its state, its buttons, and "All activity" (the new tab). Styles move from inline to classes.

**The two logged gaps are fixed**: deleting a saved custom agent asks first (`CodecShell.ask`, danger), and Send with
an empty box starts a crew that needs no text.

## API

- `GET /api/agents` — adds the progress fields above.
- `GET /api/agents/jobs` → `{jobs: [{job_id, crew, status, started, finished, steps, last, error, doc_url}]}`.
- `POST /api/agent_global_grants` refuses unsafe folder values (400), as `/api/agents/{id}/grant` does.

No change to the plan schema, the runner, the state machine or the security lists.

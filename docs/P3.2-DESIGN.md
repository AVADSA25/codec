# P3.2 — One Inbox for approvals, questions, reports and agent updates

Item 22 of docs/UI-PHASE2-3-PLAN.md. Stacked on P2.15 (#430).

## Why

What needs the owner is spread over five places that each poll on their own: a fixed approval banner on Home and
another on Chat (`/api/approvals` every 3 s each), Home's question panel (`/api/agents/pending_questions` every 8 s),
the Inbox badge (`/api/notifications/count` every 30 s on every page) and Tasks' Reports tab (`/api/notifications`
every 5 s while a job runs). The bell goes to /tasks#reports, a list without actions, and agent notifications there
have no `id`, so marking one read fails (`/api/notifications/{id}/read` raises KeyError on id-less entries).

## What

**One endpoint.** `GET /api/inbox` (routes/inbox.py) returns every item, newest first, with counts:

| Item | Source | Filter | Actions |
|---|---|---|---|
| approval | pending entries of the dashboard's approval queue (not expired) | Needs you | Allow once, Deny (existing `/api/approvals/{id}/allow|deny`) |
| question | `codec_ask_user` pending questions before their deadline | Needs you | its options and a text answer (`/api/agents/answer/{qid}`); a strict-consent question says which word to type |
| report | `task_report` and `shift_report` notifications | Reports | Open (marks it read; a document link opens the document), Discuss in chat |
| agent | `agent_*` notifications; the agent's current status from its manifest | Agents, or Needs you while the agent is blocked | Pause (running), Resume (paused or blocked without a grant), Grant (blocked on a permission; asks first) |
| suggestion | `proactive_suggestion` notifications | Suggestions | its own buttons, only to `/api/proactive/acknowledge|dismiss` |

`question` notifications are left out (the pending question is the item). Notifications without an `id` get a
stable one (`auto_` + a hash of type, agent and time). The list carries a 300-character preview; `GET
/api/inbox/item/{id}` returns one item's full text (for Open and for Chat). `POST /api/inbox/read {"ids": [...]}`
marks items read (and writes the id onto an id-less notification), under the same two locks every notifications
writer uses. Agent and suggestion actions come from the server, which only emits the endpoints above; a Grant's
kind is inferred from the block reason as Chat already does, and its value is the permission the agent asked for.
No "always allow" (the plan's rule).

Counts: `needs_you` (approvals + questions + blocked agents), unread `reports`, `agents`, `suggestions`, and
`badge` = needs_you + all unread.

**One drawer** (static/codec-shell.js, every page). The sidebar's Inbox row, the phone tab bar's Inbox tab and the
palette's Inbox entry open it in place (a drawer from the right on a desktop, a bottom sheet on the phone; a
`data-dialog`, so Tab stays inside, Esc closes, focus returns). Filters: Needs you, Reports, Agents, Suggestions, each
with its count; it opens on Needs you when something waits. "Mark all read" for the open filter. `/#inbox` (or
`#inbox=reports` etc.) opens it on any page; old `/tasks#reports` links open it on Reports. Phone pushes for
approvals, questions and agents now open `/#inbox`.

**One poller.** The shell polls `/api/inbox`: every 15 s while the page is visible, 5 s while something needs the
owner or the drawer is open, 60 s while the page is hidden, and at once after any action or when the page comes
back. When a new Needs-you item arrives it shows a toast with Open (and a desktop notification if the page already has
that permission; no permission prompt).

**Pages.** Home's and Chat's approval banners and their pollers are removed. Home's question panel in Flash stays,
but it is fed by the shell's inbox data and built by the same shared card (`CodecShell.questionCard`), the one the
drawer uses. Tasks loses its Reports tab and its poller. Chat opens `/chat#report=<id>`: a new chat whose first
message is that report (only the id travels in the link, as with P3.1's `#card=`).

## API or schema change

New: `GET /api/inbox`, `GET /api/inbox/item/{id}`, `POST /api/inbox/read`. `codec_push.KINDS` URLs for approval,
question and the agent kinds become `/#inbox`. `/api/notifications/{id}/read` no longer fails on an id-less entry.
No change to notifications.json's format, the approval queue, pending questions or any security list.

## Test plan

`tests/test_inbox.py`: the merge (pending-only approvals, unexpired questions, groups, question notifications left
out, blocked agents in Needs you, stable ids), only allowed action endpoints, Grant's kind and value, counts and
badge, the preview and the full text, marking read by real and computed id, and the wiring (one poller; no page polls
approvals, questions or the count; links open the drawer; Home uses the shared card; Chat's `#report=`; no Reports
tab; push URLs). Under jsdom: the drawer renders the filters and counts, Allow once and an option answer post to the
right endpoints, Open marks an item read, Grant asks before posting.

Mac test before merge: drawer and sheet at 1470x956 and 375x812, light theme; an approval from a session, an
ask_user question, a finished schedule and an agent; keyboard only; console clean.

## Rollback

Revert the PR: the banners, the Reports tab and the five pollers come back.

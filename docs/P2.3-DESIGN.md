# P2.3 — '/' commands, '@' skills and agents, and a Cmd+K palette

Item 13 of docs/UI-PHASE2-3-PLAN.md.

## Why

The slash commands (`/help`, `/skills`, `/cost`, `/status`, …) are only discoverable by sending `/help`. Skills
run only when a message happens to match a trigger, so there is no sure way to say "use this one". Nothing on any
page is reachable from the keyboard except the sidebar search.

## What

- **`GET /api/slash_commands`**: the registry (`codec_slash_commands.SLASH_COMMANDS`): name, summary, usage,
  aliases.
- **`GET /api/mentions`**: what '@' can pick, each with a label and a one-line description:
  - skills a chat message may run (`CHAT_SKILL_ALLOWLIST`, the same set the automatic skill routing uses) that the
    registry knows, by their registry `SKILL_NAME` (so "AI News Digest", not a file name), in plain groups
    (Google, Browser, Mac, Memory and notes, Reports, Home and media, Tools, Other). `create_skill` is left out:
    it has its own brief-and-confirm flow in chat.
  - crews (`CREW_REGISTRY`: name, label, description, the argument the task fills);
  - saved custom agents (`~/.codec/agents/*.json`: id, name, role);
  - MCP servers that are switched on (`~/.codec/mcp_servers.json`).
- **Chat composer, '/'**: typing '/' at the start opens a popover filtered as you type: the backend commands (with
  their usage) and five page actions: `/new` (new chat), `/brief` (run the Morning briefing now), `/image`,
  `/think`, `/project` (switch mode). A backend command is inserted as text for arguments and sent as today; a
  page action runs at once. Up/Down, Enter or Tab, Esc; a click works too.
- **Chat composer, '@'**: typing '@' at the start or after a space opens a grouped picker (Skills by group, Crews,
  Agents, MCP servers), filtered by the text after '@'. Picking removes the '@text' and puts one chip in the
  composer (a new pick replaces it; x removes it):
  - a **skill** chip sends the new `skill` body field with the next message; `/api/chat` then runs exactly that
    skill with the message, without trigger matching;
  - an **MCP server** chip sends `skill: "mcp:<server>"`: the message runs as `call <server> <tool> {json}` when it
    has that shape, otherwise CODEC lists the server's tools (what the `mcp_connect` skill supports today);
  - a **crew** or **agent** chip switches the composer to Agents with that crew (or the saved agent's role, tools
    and steps) and the message becomes its task, through the existing `/api/agents/run` flow with its progress and
    Stop. Every crew's first argument is filled from the message (from `CREW_REGISTRY`), so all 12 crews run, not
    only the four in the Agents sheet.
- **Explicit routing on the server (`routes/chat.py`)**: the `skill` field is honoured only for the skills '@'
  lists (the chat allowlist) and `mcp_connect` for `mcp:` targets, through `codec_dispatch.run_skill` (hooks,
  audit, licence), after the same consent gate as automatic routing (`codec_consent.chat_consent_ok`: destructive
  skills ask the owner first). Anything else answers "That skill can't be run from chat." and runs nothing. The
  reply has the same shape as automatic skill routing (a `skill` event, then the result).
- **Cmd+K palette (the shell, every page)**: Cmd+K (Ctrl+K elsewhere; not inside the Vibe code editor) opens a
  palette over the same data: search chats (titles first, then `/api/qchat/search` from two letters), jump to a
  page, run a skill (opens Chat with the skill chip), switch model (`POST /api/model`, the active one marked),
  start the Morning briefing, new chat, keyboard shortcuts. Up/Down, Enter, Esc; `role="dialog"`, a combobox and
  a listbox. This replaces Cmd+K's old job (focusing the sidebar search), whose first result is the same search.
- **Cmd+/**: a sheet listing the shortcuts (palette, shortcuts, sidebar, send, new line, '/', '@', Esc).

## API or schema change

`GET /api/slash_commands`, `GET /api/mentions`; `/api/chat` accepts an optional `skill` field. No database change.
`CodecShell.palette` and `CodecShell.shortcuts` open the two sheets. AGENTS.md §4 notes the explicit pick.

## Test plan

tests/test_palette.py: the two routes (every registry command with usage; skills by `SKILL_NAME` from the
allowlist only, grouped, without `create_skill`; all crews with their argument; saved agents; only switched-on MCP
servers); explicit routing runs the picked skill and not the trigger match, refuses a skill outside the list, asks
consent for a destructive one, maps `mcp:` to `mcp_connect` with `call`/`list tools on`; the chat page wires '/',
'@', the chip, the `skill` field and the crew arguments; the shell binds Cmd+K to the palette and Cmd+/ to the
sheet.

Browser (throwaway dashboard): '/' popover, filtering, a backend command and a page action; '@' groups, a skill
chip that routes the message, a crew chip into Agents, an MCP server; Cmd+K: chat search, a page, a skill into
Chat, a model switch and the briefing (the two network calls stood in, since the throwaway shares the Mac's model
server); Cmd+/; 1470x956, 375x812, light theme.

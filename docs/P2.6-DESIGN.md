# P2.6 — Styled menus and sheets instead of native select, confirm, prompt and alert

Item 15 of docs/UI-PHASE2-3-PLAN.md.

## Why

The pages still use the browser's own dialogs: `confirm()` to approve a plan, abort an agent, reset a prompt,
restart a service, delete a schedule or a Vibe project; `prompt()` for a 2FA code, a rejection reason and the hour
of a daily crew; `alert()` for results and errors. They look like a different app, block the page, cannot be
styled for the dark theme and, on the phone, break out of the PWA. Five pickers are bare `<select>`s.

## What

Two components in the shell (`static/codec-shell.js`), so every page gets the same ones:

- **`CodecShell.ask(opts)` → Promise**: one modal, a bottom sheet on the phone (the P3.3 dialog styles). Title,
  message, an optional text field (with a pattern, e.g. six digits for a 2FA code), a Cancel and a confirm button
  (red for a destructive one). It resolves `true`/`false`, or the text/`null` when it has a field. Enter confirms,
  Esc and the backdrop cancel, focus moves into it and back to where it was.
- **`CodecShell.menu(select)`**: turns a native `<select>` into a button that opens a keyboard-navigable popover
  list (`role="listbox"`, Up/Down, Home/End, Enter, Esc, type to jump). The `<select>` stays the source of truth:
  picking sets its value and fires its `change`, so the page's handlers keep working; a page that rebuilds the
  options just calls `sync()`.

Where they go:

- **Pickers** (Chat): the model, the research model, the image size and "Load saved" agents use `CodecShell.menu`.
  The crew picker has been a styled sheet since UI phase 1, and deleting a chat already confirms in the list
  (P2.2), so neither changes.
- **Modal**: approve plan, reject reason (with a field), abort agent (Chat); 2FA disable and re-enable (a
  six-digit field) and prompt reset, trigger reset (Home); service restart (Cortex); schedule delete (Tasks);
  project delete (Vibe).
- **Toasts**: every `alert()` goes through the page's toast (Home, Cortex, Tasks, Vibe). Vibe's Screenshot posted
  to the GET-only route and did nothing (logged in known-issues for this item): it now opens the image in the page's
  existing viewer, like Voice.
- **Schedule daily** (Chat, Agents sheet) asked for a whole hour with `prompt()`; it now opens the shell's schedule
  sheet for that crew (a task and a plain-language time, "weekdays at 7:30"), which saves a crew job like Tasks does.
- **Controls**: the bare "Transparent" checkbox (Image mode) becomes a switch; the Max Steps number box (custom
  agent) becomes a stepper (− 8 +, 1 to 20).

## API or schema change

None on the server. `CodecShell.ask`, `CodecShell.menu`; `CodecShell.schedule.open({kind: 'crew', crew, label})`.

## Test plan

tests/test_native_dialogs.py: no page or shell script calls `confirm(`, `prompt(` or `alert(` (the PWA install
prompt's `.prompt()` is not one); the shell exports `ask` and `menu` with their keyboard handling; the five
pickers use `CodecShell.menu`; each former dialog calls `CodecShell.ask`; Schedule daily opens the crew sheet;
the switch and the stepper; Vibe's screenshot uses GET and the viewer. Under jsdom (skipped without it): `ask`
resolves true, false, the text or null, and `menu` changes the select and fires `change`.

Browser (throwaway dashboard): each dialog and picker by keyboard and mouse, the crew schedule sheet saves a job,
the switch and the stepper; 1470x956, 375x812 (bottom sheet), light theme; no console errors.

## Rollback

Revert the PR; the native dialogs come back.

# P2.10 — Settings with human labels, help text and proper controls

Item 17 of docs/UI-PHASE2-3-PLAN.md.

## Why

The Settings card lists raw config keys (`llm_base_url`, `wake_energy`, `stt_engine`) as text boxes, with one
"Save Changes" button at the bottom. Only the wake-word switch saves by itself. Numbers are typed as free text, a
choice of engine is a text box, and there is no help. Several features that have real settings (the shift report,
the observer, Daybreak, question timeout, step budget, image generation) have no place in Settings at all, and
`PUT /api/config` flattens every block to the top level, so it cannot write them: the Page Customization switches
(`{"ui_prefs": {...}}`) have been landing as loose top-level keys.

## What

**One schema, one renderer.** `SETTINGS_SCHEMA` in `codec_dashboard.html` lists every section and field: a friendly
label, a one-line help text, and a control:

- a switch for yes/no values;
- a dropdown for choices (LLM provider, speech engines, step budget 5 / 8 / 10, image count);
- a slider with its value for bounded numbers (wake sensitivity, observer cadence, question timeout);
- a number box with a unit, a text box, a password box for secrets (still masked), a comma list for phrases.

**Instant save everywhere.** Each field saves by itself, like the wake-word switch did: a switch, dropdown or slider
on change; a text box on change (Enter or leaving the field). The row shows "Saved" or the error, and a failed save
puts the old value back. The "Save Changes" button goes. The wake-word switch keeps its own messages.

**Sections.** The existing ones keep their order (Identity, LLM, Vision, Text-to-Speech, Speech-to-Text, Hotkeys,
Wake Word, Authentication), then new ones, each writing its own block in config.json:

| Section | Block | Fields |
|---|---|---|
| Shift report | `shift_report` | on, time of day (hour, minute), idle minutes, look-back hours, save folder |
| Observer | `observer` | on, read text on screen (OCR), active and idle cadence (30 s minimum) |
| Morning briefing sources | `daybreak` | calendar, email, weather, reminders, time budget |
| Questions | `ask_user` | answer timeout |
| Step budget | `step_budget` | chat and voice steps per turn (5, 8 or 10: "tune up before tuning out") |
| Image generation | `image` | steps, images per request, free memory needed |

**Observer on/off.** `codec_observer._enabled()` also reads `observer.enabled` (default true); the
`OBSERVER_ENABLED` env var still wins when false. Turning it off from Settings stops polling and prompt injection
and deletes the disk mirror, exactly like the kill switch (the daemon already does that when `_enabled()` is false).

**Advanced.** A collapsed "Advanced: edit config.json" section shows the whole file as JSON (secrets masked). Save
merges it: keys in the editor replace the saved ones, keys removed from the editor are **kept** (nothing is ever
deleted from config.json this way; the page says so). Masked secrets and `llm_local_restore` (owned by the model
switch, AGENTS.md §10) are read-only: they are left as saved whatever the editor holds. The same validation rules
run; a JSON syntax error is shown before anything is sent.

**Nested writes.** `PUT /api/config` accepts the old grouped sections (flattened to the top level, as today) and
the nested blocks above plus `ui_prefs` (merged into `config[block]`, never replacing sibling keys), each with its
own validation rules. The loose top-level keys earlier `ui_prefs` saves left behind are not deleted.

**Links.** `/#settings` already opens Settings (`_tabFromHash`, P2.1); the test pins it.

## API or schema change

- `GET /api/config` returns the new blocks (with defaults) next to the old sections.
- `PUT /api/config`: nested blocks `shift_report`, `observer`, `daybreak`, `ask_user`, `step_budget`, `image`,
  `ui_prefs` are merged into their block; new validation rules for their fields.
- `GET /api/config/raw` and `PUT /api/config/raw` (merge, never delete; masked secrets and `llm_local_restore` kept).
- config.json: `observer.enabled` (new, default true). No other new keys; the rest already exist with these defaults.

## Test plan

tests/test_settings_friendly.py: nested blocks merge without touching siblings or flattening; `ui_prefs` lands as a
block; validation (cadence under 30 s, step budget outside 5/8/10, bad hour) is refused; old grouped sections still
flatten; GET carries the blocks with defaults; raw GET masks secrets; raw PUT merges, keeps removed keys, keeps
masked secrets and `llm_local_restore`, refuses a non-object; `observer.enabled=false` disables the observer and the
env var still wins; the page has a label and help for every field the API returns, no raw key is shown as a label,
every field saves on its own (no Save Changes button), `/#settings` opens the panel.

Negative control: the new tests fail on the base commit.

Browser (on the Mac): each control saves and survives a reload; a bad value reverts with the error; Advanced saves
a change and keeps a removed key; 1470x956, 375x812, light theme; no console errors.

## Rollback

Revert the PR. Blocks written by the new sections stay in config.json and keep working (the features read them
already); `observer.enabled=false` would then be ignored, so turn it back on first if it was off.

# P3.11 — Usage and cloud spend

Item 29 of docs/UI-PHASE2-3-PLAN.md. Stacked on P3.10 (#437).

## Why

What a cloud model has cost this month shows only as a line in the model picker, the automatic cloud fallback can
only be set in `config.json`, nothing says whether CODEC is on the cloud right now or why, and there is no record of how
many replies ran locally or in the cloud, which skills run most, or how fast replies come over time.

## What

A **Usage** section in Settings:

- **Right now**: on the local model, or on a cloud model and why: picked in the model picker, or moved there
  automatically (`llm_auto_fallback_active`) at a given time because the local model stopped answering, with how it
  comes back.
- **Cloud spend this month**: for each registered cloud model, the spend against `monthly_cap_usd` with a bar, a note
  when it is at the cap, and the three months before, all straight from `codec_cloud_models` and its ledger.
- **Automatic cloud fallback**: Off, or one of the registered cloud entries (nothing else can be picked), with a plain
  line on when it triggers and that it counts toward the cap. Saved to `config.json:llm_auto_fallback` under the
  config lock; Off removes the key. Turning it off while CODEC is on the cloud automatically does not strand it: the
  switch back follows `llm_auto_fallback_active`, as before. Audited as `auto_fallback_set`.
- **Replies in the last 7 days**: how many ran on this Mac and how many in the cloud (chat and voice).
- **Busiest skills, last 7 days**: from the audit log. `codec_audit.get_stats` gains a `by_tool` count (skill runs:
  `tool_result` from MCP and crews, `wake_dispatch` from chat, voice and the wake word) and is asked for 168 hours.
- **Reply speed, last 14 days**: per model, the average tokens per second per day, as small bars, from the new
  per-reply log.

**Per-reply log.** `codec_usage.record_reply` appends one line per chat reply (stream and non-stream) and voice reply to
`~/.codec/reply_stats.jsonl` (0600): time, source, model, local or cloud, and for chat its tokens, tokens per second and
time. Never the question or the answer. It is trimmed to 30 days when it passes 2 MB. A failure to write never breaks a
reply. The test suite points it (and P3.8's `agent_jobs.json`) at a tmp path from conftest, like the audit log.

## API

- `GET /api/usage` → `{now: {cloud, label, auto, since}, cloud: [{id, label, spent, cap, months}], fallback: {value,
  choices, note}, replies: {days, replies: {local, cloud}, by_source, speed: [{day, model, cloud, tok_s, replies}],
  since}, skills: [{name, count}]}`.
- `PUT /api/usage/auto_fallback` `{value: id | null}` → `{value}`; 400 for anything but a registered cloud entry or null.

No change to the cap, the ledger, the switch logic or the audit envelope.

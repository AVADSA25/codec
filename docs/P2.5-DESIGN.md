# P2.5 — Dictation through CODEC's local Whisper, not Google

Item 6 of docs/UI-PHASE2-3-PLAN.md.

## Why

The mic buttons on Chat, Home (Flash) and Vibe use the browser's Web Speech API with `lang='en-US'`. In Chrome
that sends the audio to Google. CODEC already runs Whisper on the Mac (PM2 `whisper-stt`, `stt_url`), so dictation
can stay local.

## What

- **`POST /api/transcribe`** (`routes/transcribe.py`, behind the dashboard login and the CSRF check like every
  `/api` POST): takes one audio file (multipart field `file`), at most 8 MB, `audio/*` or `video/webm` / `video/mp4`
  types only (Safari labels its recordings `audio/mp4`, some Chrome builds `video/webm`). It posts the audio to the
  configured `stt_url` (default `http://localhost:8084/v1/audio/transcriptions`) with the configured `stt_model`
  and no `language` field, so a Whisper server that auto-detects can pick French, Spanish or English. It returns
  `{"text": ...}`. The audio is never written to disk by the dashboard and never logged.
- **Filters**: the voice pipeline's noise and hallucination checks (codec_voice.py `transcribe`: a transcript that
  is only a noise word, only a known hallucination, or the same fragment repeated three times) are written once
  more as `codec_voice_filters.discard_reason(text)`, over the same word sets; `/api/transcribe` returns `""` and
  the reason for those. The voice pipeline is not changed (it also drops one-word utterances; dictation keeps them).
- **Recorder in the shell** (`static/codec-shell.js`, `CodecShell.dictation`): one tap starts recording with
  `MediaRecorder` (Opus in WebM on Chrome and Firefox, AAC in MP4 on Safari), a second tap stops it; it also stops
  by itself after about 2 seconds of silence once speech was heard, and after 2 minutes at most. While it records,
  the mic button shows a live level ring (Web Audio `AnalyserNode`) and the input's placeholder says
  "Listening... tap the mic to stop"; then "Transcribing...". The transcript is added to the input for review;
  nothing is sent until the user sends it.
- **Pages**: Chat, Home and Vibe call the shell (`CodecShell.dictation.toggle(button, input)`), replacing their
  three copies of the Web Speech code.
- **Web Speech opt-in**: quick settings gets a "Browser dictation" switch, off by default, labelled "uses your
  browser's cloud service". It is stored per device (localStorage) and shown only where the browser has Web
  Speech. When on, the mic uses Web Speech as before (with the page language, not a fixed `en-US`).
- Errors say what to do: microphone blocked, no microphone, Whisper not reachable ("Dictation needs CODEC's
  speech service (whisper-stt) on the Mac"), nothing heard.

## Not in this item

Changing the Whisper server. The running `whisper-stt` is `~/whisper_server.py` (outside the repo); it passes
`--language en` when the request has no language, so dictation stays English until that server treats a missing
language as "detect". That is a small change to a live service plus a restart of `whisper-stt`, which this
plan does not pre-approve: it is left for the owner (see the PR).

## API or schema change

New route `POST /api/transcribe`. New per-device localStorage key `codec-dictation` (`local` or `browser`). No
server-side data.

## Test plan

tests/test_transcribe.py: the route forwards the audio with the model and without a language, returns the text,
refuses a file over 8 MB (413) and a non-audio type (415) without calling Whisper, maps a Whisper failure to 502
and an unreachable server to 503, and applies `discard_reason` (noise word, hallucination, repetition give `""`;
normal text and a French sentence pass). `discard_reason` matches the voice pipeline's checks. The shell has the
recorder API, the silence stop, the 2-minute cap and the opt-in row; the three pages call it and no page sets
`lang='en-US'` any more; the route is mounted and CSRF-checked.

End to end: a spoken sentence (macOS `say`, converted to Opus WebM with ffmpeg) goes through `/api/transcribe` on
the throwaway dashboard to the real `whisper-stt` and comes back as text. Browser: the same audio played into a
stand-in microphone stream goes through the recorder, the level ring moves, the text lands in the input on Chat,
Home and Vibe; the opt-in switch; 1470x956, 375x812, light theme.

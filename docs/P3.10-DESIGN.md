# P3.10 — Side-by-side model compare from any reply

Item 28 of docs/UI-PHASE2-3-PLAN.md. Stacked on P3.9 (#436).

## Why

`codec_compare` can fan one prompt out to several models, but only through the `compare` skill, which prints the
answers one after another, with no token counts, and sends the prompt to every tier at once, the AVA cloud tiers
included, without asking. In Chat there is no way to ask "would the other model have answered this better?" and keep
the better answer.

## What

**Compare models** in a reply's more menu (P2.7) opens a dialog for the question behind that reply:

- **Model A** is the local model: the one Chat uses when it is local, otherwise the local model a switch back would
  restore (`codec_cloud_models.local_only`). Only one local model is loaded at a time, so there is no second local
  variant of the same server.
- **Model B** is picked from the other targets: each model Cookbook serves (local, on its own port) and each
  registered cloud model (`extra_models` with a non-local `base_url`). A cloud model shows this month's spend against
  its cap, and Compare stays off until **Use the cloud for this compare** is ticked; the server refuses a cloud target
  without that opt-in. The cloud leg goes through `codec_llm.call`, so the licence gate, the key, the monthly cap and
  the spend ledger apply as for any cloud reply. The AVA tiers the skill uses are not offered here (they do not pass
  the capped path). With no second target, the dialog says how to get one.
- The answers show side by side (stacked on the phone), each with its time, tokens and tokens per second (*about*
  when the server sent no token count and it is estimated from the text), or its error.
- **Keep this one** puts that answer into the chat as a new version of the reply (P2.7 versions): the old answer
  stays one step back with the version arrows, and the saved chat follows. Kept on an older reply, the later turns
  stay with the earlier version, as an edit does.

The question is compared on its own, without the rest of the chat; the dialog says so.

**Token counts.** `codec_llm.call` gains an optional `usage_out` dict that receives the server's `usage` block.
`codec_compare._query_one` fills `tokens`, `tokens_estimated` and `tok_s` (completion tokens over the leg's
wall time) for every leg; the skill's output is unchanged.

## API

- `GET /api/compare/targets` → `{local: {id, label, model}, targets: [{id, label, kind: "local"|"cloud", spent,
  cap}]}`.
- `POST /api/compare` `{prompt, target, cloud_ok}` → `{results: [{label, model, tier, ok, response | error,
  elapsed_ms, tokens, tokens_estimated, tok_s}]}`. 400 for an empty or over-long prompt (8,000 characters) or an
  unknown target; 403 for a cloud target without `cloud_ok`. Audited as `compare_run` (target id, kind, outcome; no
  prompt or answer).

No change to the compare skill's endpoint set, the model picker, the cap or the spend ledger.

# P2.12 — Thumbnails for attachments and a lightbox

Item 19 of docs/UI-PHASE2-3-PLAN.md.

## Why

An attached photo shows as a file name in a small chip ("photo.jpg (analyzing...)"), and once sent it is a line of
text in the message. There is no way to see what was sent, or to look at a chat image or a generated image larger
without opening a new tab. The vision model's description of a photo is sent to the model but never shown.

## What

**Tiles in the composer.** An image tile shows a 56px thumbnail, made in the browser as a ~112px JPEG (never the
original). Any other file shows its icon, name and size. While a file is read or analysed, its tile shows a progress
ring (still under `prefers-reduced-motion`). The x still removes it.

**Sent messages keep their tiles.** The user message shows the same tiles above its text (images as thumbnails,
other files as icon, name and size). They are saved with the message, so a reload shows them.

- Storage: a new nullable `attachments` column on `qchat_messages` (JSON list). Added once, after a backup copy
  `qchat.db.bak-p2.12` (owner-only, only when the database has rows). No row or column is deleted.
- Each tile holds `name`, `kind` (image, pdf, text or file), `size`, for an image a `thumb` (a JPEG data URL, at
  most 16,000 characters, checked against `data:image/jpeg;base64,...`) and `saw` (the vision description, at most
  4,000 characters). The server drops anything else: other image types, longer thumbnails, unknown keys, more than 8
  tiles. File text is never stored here (it is already part of what was sent to the model, as before).
- Markdown export lists the attached names; JSON export lists the tiles without thumbnails.
- P2.7 versions re-save a message with its tiles.

**What CODEC saw.** For an image, the vision description still goes to the model in the message; on screen it sits
in a collapsed "What CODEC saw" under the message.

**Lightbox.** Clicking a sent image tile, or a generated image (Image mode), opens the existing `#screenModal`
larger, with a Download button. For an image sent in this page session the 1280px copy already in the browser is
shown; after a reload, the thumbnail. Esc, the close button and the backdrop close it and focus returns to the tile.
The webcam snapshot uses the same lightbox. Only same-origin generated image URLs and JPEG/PNG data URLs open.

## API or schema change

- `qchat_messages.attachments TEXT` (nullable, additive, backup first).
- `POST /api/qchat/save`: each message may carry `attachments` (sanitised as above).
- `GET /api/qchat/session/{sid}`: messages carry `attachments` when they have tiles.

## Test plan

tests/test_attachment_tiles.py: save and load round-trip; sanitising (PNG/SVG/script thumbnails dropped, too long
dropped, kinds normalised, at most 8 tiles, `saw` capped, no file text); backup before the column on a database with
rows and none for an empty one; export lists names and no thumbnails; the page builds tiles with a thumbnail or icon,
name and size, a progress ring, keeps tiles on sent and loaded messages, folds the vision text into "What CODEC saw",
and opens chat and generated images in the lightbox with Download; the lightbox refuses other URLs.

Negative control: the new tests fail on the base commit.

Browser (on the Mac): attach a photo and a PDF, send, reload; open the photo and a generated image; 1470x956,
375x812, light theme; no console errors.

## Rollback

Revert the PR. The `attachments` column stays (unread); `qchat.db.bak-p2.12` can be deleted by hand.

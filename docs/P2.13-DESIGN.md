# P2.13 — Accessibility baseline

Item 20 of docs/UI-PHASE2-3-PLAN.md.

## Why

Screen readers hear "button" for icon-only buttons, nothing when a reply arrives, and nothing when a toast says a
save failed. Thirteen style rules remove the focus outline with nothing in its place, so a keyboard user cannot see
where they are. Some controls are clickable spans and divs that a keyboard cannot reach. Modals do not keep focus
inside them, and closing one leaves focus nowhere. The 2FA code boxes cannot be filled by the phone's code autofill.
Nothing respects "reduce motion" outside the voice orb.

## What

- **Names.** Every icon-only `<button>` on the pages gets an `aria-label` (its title where it had one; the auth
  page's theme button gets "Switch light or dark theme"). A test scans all pages so a new one cannot slip in.
- **Live regions.** Chat `#messages` and the voice transcript are `role="log" aria-live="polite"`; the page toasts
  (Chat, Home, Tasks) are `role="status"` (the shell toast already was).
- **Focus ring.** The global `:focus-visible` ring in codec.css now shows on every control: the 13 bare
  `outline: none` rules (inputs, selects, text areas on Audit, Auth, Chat, Cortex, Home, Tasks, Vibe) are removed.
  Rules that replace the outline with the focus ring shadow, and inputs whose container shows focus (the sidebar
  search, the composer), stay.
- **Real buttons.** The file tile's remove x, Vibe's "+ New Project" and Vibe's remove-folder x become `<button>`s.
  Rows that hold other content and cannot be one (a prompt header in Settings, a report card in Tasks, a Vibe project
  row) are `role="button" tabindex="0"`, and the shell presses them on Enter or Space. The fingerprint ring on the
  login page duplicates the "Authenticate with Touch ID" button and is hidden from assistive tech. The Audit pills
  and rows are left to P2.15, which rebuilds them.
- **Dialogs.** A shell helper watches every element marked `data-dialog`: while it is shown, Tab stays inside it, Esc
  presses its `[data-dialog-close]` button, and focus returns to where it was when it closes. Marked: the quick
  settings panel, the image viewer on Chat, Home, Vibe and Voice, the Tasks preview, the Chat Agents sheet and the
  Vibe projects drawer. Each is `role="dialog" aria-modal="true"` with a label. The shell's own ask and schedule
  dialogs already did this.
- **Toggles and tabs.** Voice replies and Wake word in quick settings carry `aria-pressed`. Tasks tabs are a
  `role="tablist"` of `role="tab"` buttons with `aria-selected` and `aria-controls`, panels `role="tabpanel"`; the
  Settings sub-navigation buttons get `role="tab"`.
- **2FA.** The first code box has `autocomplete="one-time-code"` and takes a whole code (autofill or paste) and
  spreads it over the six boxes; every box has a label.
- **Reduced motion.** One `prefers-reduced-motion: reduce` block in codec.css stops animations, transitions and smooth
  scrolling on every page.
- The stale jsdom shell-order test from known-issues is fixed (P2.8's reading strip mounts before the tab bar).

## API or schema change

None on the server. `CodecShell.watchDialogs()` (for pages that add a `data-dialog` later).

## Test plan

tests/test_a11y_baseline.py: no icon-only button without a name on any page or in the shell; the live regions and
status roles; no bare `outline: none` left (an outline removal must sit with a `box-shadow` focus ring or a
`:focus-within` container); the converted buttons and role=button rows; every `data-dialog` has `role="dialog"`,
`aria-modal`, a label and a `[data-dialog-close]`; tabs and pressed states; the 2FA autofill; the reduced-motion
block. Under jsdom (skipped without it): a shown dialog takes focus, Tab wraps inside it, Esc closes it and focus
returns; Enter presses a role=button row.

Negative control: the new tests fail on the base commit.

Browser (on the Mac): keyboard only through Chat, Home Settings, Tasks and Vibe; VoiceOver reads a new reply and a
toast; 1470x956, 375x812, light theme; reduce motion on in macOS; no console errors.

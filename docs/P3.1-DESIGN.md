# P3.1 — Morning briefing that runs by itself, speaks, then leaves a card

Item 9 of docs/UI-PHASE2-3-PLAN.md. Decision 2026-09-29 (DECISIONS.md): off by default, switched on in Settings;
the owner's own install keeps it off.

## Why

The Daybreak briefing (`daily_kickoff`) only runs when asked. Other CODEC users want it ready in the morning,
said out loud when they sit down, and left on Home.

## What

- **The job**: a P3.3 schedule job with the fixed id `sched_morning_briefing` (kind `skill`, skill
  `daily_kickoff`, task "start my day", default "weekdays at 7:30", delivery `briefing`). It is created only when
  the owner switches the briefing on in Settings; Tasks lists it as "Set up in Settings" (no Edit there). It does
  not start while an image job holds `~/.codec/image_job.lock` or the Mac has under 4 GB free (the P3.3 catch-up
  runs it later, for up to 12 hours).
- **Delivery** (`codec_briefing.deliver`):
  1. The loaded local model turns the briefing into a 45-60 second script (110-150 words, no lists, no links, never
     the word "CODEC", which would wake the wake-word listener). If the model fails, a plain-text cut of the
     briefing is used.
  2. A `briefing` card on Home (the P3.3 Today store) with the full briefing and the open Daybreak threads.
     Actions: Open in chat, Snooze (2 hours), Dismiss; per thread Done (closes it with `codec_daybreak`) and, for
     waiting-on and follow-up threads, Draft reply (opens a new chat with a draft in the box, not sent).
  3. A content-free Web Push "Your briefing is ready" (`codec_push.notify("briefing")`, its own switch).
  4. If speaking is on, the script waits in `~/.codec/briefing_state.json` for today.
- **Speaking at the first activity** (`codec_briefing.tick`, run by the scheduler loop every minute): when a
  script is waiting, the Mac has had keyboard or mouse input in the last 60 seconds (the observer's idle signal),
  no voice call is on, no image job runs, and it is before noon, CODEC plays a chime and says the script with
  Kokoro, sentence by sentence. Never to an empty room: if nobody comes before noon, it stays unsaid (the card
  remains). Stop: the card's Stop button, saying the wake word (a `wake_word_detected` line appears in the audit
  log), or starting a voice call. Talking over it without the wake word does not stop it (no echo-cancelled
  listening in the dashboard).
- **Settings** (Home, Settings, General, "Morning briefing"): On, When (plain language with its reading), "Say it
  on the Mac when you first sit down", Try it now. `GET/PUT /api/briefing`, `POST /api/briefing/run`,
  `POST /api/briefing/stop`.
- **Chat** accepts `#card=<id>` (only a card id): opens a new chat seeded with that card's text as CODEC's
  message. A Draft reply hands its text over through sessionStorage, never through the URL.
- docs/DAYBREAK-DESIGN.md: its "no notifications posted" line now points here for opted-in users.

## Not in this item

Voice barge-in without the wake word. Changing what `daily_kickoff` gathers.

## API or schema change

`GET/PUT /api/briefing`, `POST /api/briefing/run`, `POST /api/briefing/stop`, `GET /api/today/{id}`,
`POST /api/today/{id}/snooze`, `POST /api/today/threads/done`. Today cards gain `threads` and `snoozed_until`.
New file `~/.codec/briefing_state.json`. Scheduler delivery `briefing` (internal, not offered in the Tasks form).

## Test plan

disables it, a new When is read in plain language; the job waits while an image job or low memory; delivery makes
the script (and falls back without the model; "CODEC" never in it), the card with threads, the push, the waiting
script; `tick` speaks only when active, before noon, without a voice call or image job, once; the speaker stops on
Stop, on a wake-word audit line, on a voice call; thread Done closes the Daybreak thread and leaves the card; snooze
hides until the time; Tasks shows the job as set up in Settings; Chat's `#card=` accepts only a card id; Settings
section present.

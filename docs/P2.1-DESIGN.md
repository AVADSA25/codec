# P2.1 — Desktop sidebar, phone tab bar, and every page on the shared shell

Item 2 of docs/UI-PHASE2-3-PLAN.md. Source: the UI review of 2026-09-28 (design brief: DESKTOP LAYOUT,
PHONE LAYOUT, TYPE SCALE).

## Why

Seven pages (Home, Chat, Voice, Vibe, Tasks, Cortex, Audit) each carry their own copy of the header, the
top nav, the "MENU" side panel, the CSS for all three and the JS behind them (theme, text size, lock,
notification polling). The copies have drifted: three theme controls, two text-size mechanisms (five pages
still root-zoom), and a house icon titled "Home" that opens a settings panel. Chat's history drawer is
hidden behind a button on the desktop, and on the phone the nav and the composer are `position:fixed`
with measured padding.

## What

### One shell for seven pages

- `static/codec-shell.js` (new, stamped like codec.css) builds the shell. Each page loads it as the first
  element of `<body>`: `<script src="/static/codec-shell.js?v=…" data-page="chat" data-title="Chat"
  [data-status] [data-model-slot]></script>`. It runs synchronously, so every id that page code expects
  (`sidePanel`, `voiceState`, `muteX1/2`, `textSizeGroup`, `wakeState`, `statusDot`, `hdrModelSlot`,
  `menuBtn`) exists before the page's own scripts run.
- The shell CSS moves into `static/codec.css` ("App shell" section). The pages lose their header, nav and
  side-panel markup and CSS.
- Shared behaviour moves into the shell and out of the pages: `openSidePanel`/`closeSidePanel`, theme
  (`applyTheme`, `setThemePref`, `toggleTheme`, the three-way control on every page), text size
  (`applyTextSize`, `setTextSize`), `lockSession`, the wake-word toggle, and the notification-count poll
  (one 30-second poll per page, as today). The globals keep their names, so existing page calls keep
  working. A page that needs to react to a theme change listens for the `codec-theme` event.
- Auth (`/auth`) gets no shell: it is the login page.

### Desktop (1024px and wider)

A fixed 272px sidebar on `--surface`, collapsible to a 64px icon rail with Cmd+Shift+S (remembered in
localStorage `codec-sidebar`). Between 768 and 1023px it starts as the rail. Content:

- the 20px CODEC mark and the wordmark (Sans 600), plus the collapse button;
- a full-width "New chat" button (pencil icon, 36px, radius 12): on Chat it starts a new chat, elsewhere it
  opens `/chat#new`;
- a search row with a "Cmd K" / "Ctrl K" hint in 12px mono. Until the P2.3 palette, Cmd+K focuses it; it
  searches chats through the existing `/api/qchat/search`;
- nav rows Today (`/`), Chat, Voice, Vibe, Tasks: 20px icon, 14/500 label, 36px, radius 8, the active row on
  surface-3;
- the chat history from `/api/qchat/sessions` (the list chat's drawer shows today: title, time, delete);
  a row opens the chat in place on Chat and `/chat#session=<id>` elsewhere. Pinned, date groups and the
  three-dot menu are P2.2;
- at the bottom: Inbox with a count badge (to `/tasks#reports` until the P3.2 Inbox), Settings
  (`/#settings`) and a profile row ("You") with Lock.

The main column keeps a slim top bar: the page title, the page's own items, and the quick-settings button,
which gets a sliders icon instead of the house icon titled "Home".

### Phone (under 768px)

- A 52px top bar plus the safe area: the menu button on the left opens the sidebar as a drawer (85% wide,
  at most 320px, same content), the page title or Chat's model pill in the centre, and new chat plus
  quick settings on the right.
- A bottom tab bar, 56px plus the safe area: Today, Chat, Voice, Tasks, Inbox (22px icon over an 11/500
  label, 48px targets, active in accent, Inbox with its badge). Vibe and Settings are in the drawer.
- `body` is a 100dvh flex column: top bar, the page (`.cs-main`, the only scroller), tab bar. The tab bar
  and the Chat and Flash composers are in the flow, not `position:fixed`, so the measured
  `--nav-h`/`--input-h` padding and its observer go away (the #344 / 1612bf0 lesson: one column, one
  scroller, no root zoom). Drawers, sheets, toasts and the quick-settings panel stack above everything.

### Quick settings (the old MENU panel)

Voice replies, Wake word, Screenshot, Photo (webcam), Live video (the last three only on pages that have
them), Theme (Auto / Light / Dark), Text size (S / M / L), Connect AI model (Home only). Settings, Lock and
Notifications move to the sidebar (Inbox).

### Home tab row

Flash, History, Skills, Settings. Audit and Connectors move into Settings as a small sub-nav (General,
Connectors, Audit, and Cortex, which opens the Cortex page); the Cortex iframe tab goes away because
`/cortex` is its own page. Home reads the URL hash (`#settings`, `#history`, `#skills`, `#audit`,
`#connector`) on load and on `hashchange`, so the sidebar's Settings link and the old `/#settings` links
open the right panel. (P2.10 builds the friendlier Settings; this is only the link target.)

### Chat

Its drawer markup, CSS and JS go; the shell's sidebar is the history list. `loadSession`, `newChat` and
delete stay in chat and are called by the shell. Chat reads `#new` and `#session=<id>` on load. The list
refreshes after a chat is saved, started or deleted, and the open chat is highlighted.

### Page roots

Each page's content sits in one `.cs-main` element: Home and Chat's `.app`, Voice's `.call-container`, and
new wrappers on Tasks (which becomes an inner scroller), Audit, Cortex and Vibe. Cortex's many
`position:fixed` panels stay inside its main area because its wrapper is a containing block
(`transform: translateZ(0)`). Vibe's projects drawer opens beside the sidebar instead of under it.

### Type scale and text size

Voice, Vibe, Cortex, Audit and Auth move their `font-size` declarations (CSS, inline styles and generated
HTML) onto `calc(Npx * var(--fs-scale))` or the `--fs-*` tokens, with 12px as the floor (11px only for
badge digits and tab labels). SVG text inside the Cortex graph keeps its graph units (P2.15 handles Cortex
readability). S / M / L then set `--fs-scale` (0.93 / 1 / 1.12) on every page, Auth included, and the root
`zoom` and `--tz` go away everywhere.

## Not in this item

Pinned chats, date groups, the three-dot menu and paging (P2.2); the Cmd+K palette (P2.3); the right-side
sheet and the Inbox drawer (P3.2); Today content (P3.4); the voice call redesign (P2.9); Cortex readability
(P2.15); friendly Settings (P2.10).

## API or schema change

None on the server. New static file `static/codec-shell.js`, added to `tools/stamp_static.py`.

## Test plan

- `tests/test_ui_shell.py`: every app page loads the shell first in `<body>` and no longer has its own
  header, nav or side panel (markup or CSS); Auth does not load it; codec.css has the shell rules and the
  tab bar and top bar are not `position:fixed`; no page sets `style.zoom` or `--tz`; the five pages have no
  raw px `font-size`; Home's tab row has no Audit, Cortex or Connector tab and Home reads the hash; Chat
  handles `#new` and `#session=`; the shell script parses (`node --check`) and exposes the shared globals.
- Existing UI tests (composer, design system, markdown, static assets) stay green; full suite, ruff,
  `tools/stamp_static.py --check`.
- Browser, on the throwaway dashboard (:8190, temp HOME), at 1470x956 and 375x812, dark and light: all
  seven pages render the shell; sidebar collapse and Cmd+Shift+S; drawer on the phone; tab bar in the flow
  (no page scroll behind it, last message reachable above the composer); quick settings theme and text size
  apply at once on every page; history opens chats from another page; Home's Settings sub-nav.
- Live after deploy: the same pages on the live dashboard.

## Rollback

Revert the PR; the pages go back to their own copies. No stored data changes (the `codec-sidebar`
localStorage key is ignored by the old pages).

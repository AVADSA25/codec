# P2.9 — Calm voice call with standard controls

Item 11 of docs/UI-PHASE2-3-PLAN.md.

## Why

The voice call page (`codec_voice.html`) moves all the time: a ring that spins forever, pulsing rings, a
full-screen glow that changes colour with the state, waveform bars and gradient buttons with glow shadows. It
still labels the owner's lines 'M' (the owner's initial, in a public repo), uses 'SF Pro Display' instead of the
Plex type of the other pages, hides hold-to-talk (nothing says the circle can be held) and has none of the
controls a call app has: no mute, no way to stop a long answer without talking over it, no way to type.
Its Screenshot quick setting posts to a GET-only route, so it silently does nothing; its `alert()` never shows.

## What

- **One orb, flat buttons.** The spinning ring, the pulsing rings, the waveform bars and the full-screen glow go.
  One orb stays, and its size follows a level from 0 to 1. While listening, the level is the mic RMS the page
  already computes (same `rms / 2800` scale). While CODEC speaks, it is the level of the reply audio, read from an
  AnalyserNode on the playback path. While processing, the orb breathes slowly; nothing moves under
  `prefers-reduced-motion`. The `#statusLabel` caption stays the one place that names the state. The call button
  is a flat circle (success colour to start, danger colour to end), with no gradient and no glow; the mode pills
  lose their glow.
- **Transcript as chat bubbles.** Your lines are right-aligned bubbles labelled 'You' (was 'M'), CODEC's are
  left-aligned bubbles labelled 'CODEC' (the streaming line too), notes from the call are small centred lines.
  Copy transcript writes `[You]` / `[CODEC]`.
- **Plex.** The page body uses `var(--font)` (IBM Plex Sans); the timer and the transcript header use
  `var(--mono)` (IBM Plex Mono). No 'SF Pro' or 'SF Mono' remains.
- **Hold-to-talk hint.** During a call a line under the orb reads "Hold the circle to talk, let go to send".
- **Controls during a call:**
  - **Mute** switches the mic track off (`track.enabled = false`): the page keeps sending audio, now silence, so
    the server's voice detection closes any open utterance on its own and nothing said while muted is heard or
    interrupts. Holding the circle while muted unmutes for the hold (push to talk).
  - **Stop speaking**, shown while CODEC speaks or works: sends the existing `{type:'interrupt'}` and calls
    `stopAudio()`, then shows the listening state.
  - **Type box**: a text field and a Send button. Enter sends `{type:'text', text}`; the page shows your bubble at
    once. `codec_voice.py` handles the new `text` control: the text is stripped, capped at 2,000 characters and
    queued like an utterance (the same non-blocking queue). The pipeline runs a typed turn exactly like a spoken
    one (question answers, screen requests, mode commands, crews, skills, Think mode, the model) but skips speech
    to text and does not echo the user line back, since the page already shows it. The reply is spoken as usual.
  - **Tool chips**: Think mode already narrates each tool call as a system line "Using web search…". The page shows
    those as small chips ("web search") instead of note lines.
  - **Continue in chat**: saves the call's You and CODEC lines (not notes or chips) as a new chat through the
    existing `POST /api/qchat/save` (fresh session id, title "Voice call <date> <time>"), ends the call if one is
    running, and opens `/chat#session=<id>`. Disabled while the transcript has no You or CODEC line.
  - **Microphone picker**: lists the audio inputs (`enumerateDevices`); the choice is kept in this browser
    (`codec-voice-mic`) and used as `deviceId: {exact}` when the mic opens. A device that is gone falls back to the
    default with a toast. Changing it during a call swaps the mic stream only; the socket and the reply audio
    carry on. Device names show once the browser has granted the mic.
- **An empty hold or Your Turn** (nothing buffered) now gets a `listening` status back. Before, the page stayed on
  "Still working…" until the next utterance; the visible hold hint and push to talk while muted make that common.
- **Screenshot**: fetches `GET /api/screenshot`, shows the image in the page's existing viewer and says
  "Screenshot taken" in a toast; a failure says "Could not take a screenshot" in a toast. The shell exports its
  toast as `CodecShell.toast` for this.

## API or schema change

One new control message on the existing `/ws/voice` socket: `{"type": "text", "text": "..."}` (a typed turn).
`CodecShell.toast(msg, url)` is exported. No new route, no database change, no new audit event (a typed turn goes
through the same paths and audits as a spoken one).

## Test plan

tests/test_voice_call_ui.py: the `text` control queues the stripped text, caps it at 2,000 characters and ignores
an empty one; Your Turn with nothing buffered answers `listening`; the pipeline runs a typed turn without speech to text, without echoing the user line, and sends
CODEC's reply; the page has no spinning ring, glow, waveform or gradient, labels 'You' (no 'M'), uses Plex (no
SF fonts), shows the hold hint, has the Mute, Stop speaking, Type, Continue in chat and microphone controls wired
to the socket and routes, turns tool narration into chips, and takes screenshots with GET plus a toast (no
`alert(`); the shell exports `toast`. The existing shell tests (type scale, no root zoom) keep passing.

Browser (throwaway dashboard, stand-in mic): start a call, the orb follows the level, Mute, a typed turn and its
reply bubble, Stop speaking during a reply, a tool chip, Continue in chat opens the saved chat, the mic picker
lists inputs; 1470x956, 375x812 and the light theme.

## Rollback

Revert the PR. A page that sends the `text` control to an older server is ignored there (unknown control types
are skipped).

# P3.9 — Connections: Google, AI apps, bridges, permissions

Item 27 of docs/UI-PHASE2-3-PLAN.md. Stacked on P3.8 (#435).

## Why

Settings > Connectors only lists the external MCP servers CODEC can use as a client. What connects *to* CODEC, or
what CODEC depends on, is nowhere: whether Google is signed in and with which scopes (fixing it means running
`reauth_google.py` in a terminal), which AI apps hold a sign-in to CODEC's MCP server and when they last used it
(the only way to cut one off is to clear the whole OAuth state and restart `codec-mcp-http`, which signs out every
app), whether the Telegram and iMessage bridges run and are allowed to answer anyone, and which macOS permissions the
dashboard has.

## What

Four sections are added to the Connectors tab, above the existing MCP server list (which stays as it is).

**Google Workspace.** Connected or not, the account (the Gmail address, asked from Google once an hour), the scopes
CODEC needs and any that are missing, and when the access token was last renewed. **Reconnect** runs
`reauth_google.py` on the Mac; Google's sign-in page opens in the Mac's browser and its answer comes back to a
localhost port, so the button is offered and accepted only on the Mac (a request through the tunnel gets 403). While it
runs, the section says so and checks again every few seconds. `reauth_google.py` now keeps the old token until the new
one is saved (it used to rename it first, so an abandoned sign-in left Google disconnected).

**AI apps connected to CODEC.** Each app that signed in to the MCP server over OAuth (claude.ai and others): its name,
the site it signs in from, when it registered, when it last used CODEC, and whether its sign-in is live. The tools are
listed once for these apps: how many CODEC exposes over the web, which are blocked there, and which ask on the phone
first (the `_HTTP_CONSENT_REQUIRED` list). **Revoke** signs out one app: only that app's access and refresh tokens are
removed. The OAuth state is never cleared and other apps stay signed in. The app can connect again; that needs the
owner PIN like any new sign-in.

How it works across the two processes (the OAuth state lives in `codec-mcp-http`'s memory and the Keychain, so the
dashboard must not edit it):

- `codec-mcp-http` writes `~/.codec/mcp_clients.json` (0600, atomic): per client, its name, redirect host, registration
  time, last use, live token count, latest expiry and the last 8 characters of each live token (the identifiers the
  audit log already uses). Never a token, a secret or a client secret. It is written after every change to the OAuth
  state, and on use at most every 5 minutes per client.
- The dashboard's Revoke writes `~/.codec/mcp_revoke.json` (0600, atomic): `{client_id: {at, tokens}}`. Before every
  token check (`load_access_token`, `load_refresh_token`) the provider reads that file when it changed, and removes the
  listed tokens of that client plus any of its tokens issued before `at`. Tokens issued later (a reconnect) are kept,
  so the file can stay and is applied the same way after a restart. The provider saves the state the usual way and
  audits `mcp_client_revoked` (counts only).

**Bridges.** Telegram: bot token set (yes or no), `codec-telegram` running, how many chats may talk to it (none means
it answers nobody), and whether owner alerts have a chat. iMessage: `codec-imessage` running, on or off in config, how
many senders may talk to it, and whether the dashboard can read the Messages database (Full Disk Access). **Send a
test** sends one fixed line, only when clicked: Telegram to the owner alert chat (or the first allowed chat); iMessage
to an allowed sender the owner picks. The server sends only to those configured recipients, never to a typed one.
Audited as `bridge_test_sent` (bridge and outcome, no recipient).

**macOS permissions.** Best effort, for the dashboard's own process: Screen Recording and Accessibility (checked
without a prompt), Full Disk Access (can it open the Messages database), and Microphone and Automation (cannot be
checked without a prompt, so they say "checked when first used"). Each has the System Settings path in words and, in a
browser on the Mac, an Open System Settings link.

## API

- `GET /api/connections/google` → `{connected, account, scopes: [{name, ok}], missing, renewed, reconnect: {allowed,
  running}}`. `POST /api/connections/google/reconnect` → `{started}` (403 off the Mac, 409 while one runs).
- `GET /api/connections/apps` → `{apps: [{client_id, name, host, registered, last_used, live, tokens, expires}],
  tools: {exposed, blocked: [...], asks: [...]}, mirror: bool}`. `POST /api/connections/apps/revoke` `{client_id}` →
  `{requested}` (404 for an unknown client).
- `GET /api/connections/bridges` → `{telegram: {...}, imessage: {...}}`. `POST /api/connections/bridges/test`
  `{bridge, to?}` → `{sent}`.
- `GET /api/connections/permissions` → `{items: [{key, name, state, where, url}]}`.

No change to the token TTLs, the security lists, the consent page or the Keychain slot. The OAuth state blob keeps its
shape.

## Rollback

Revert the PR. `~/.codec/mcp_clients.json` and `~/.codec/mcp_revoke.json` are then ignored; revoked tokens stay
revoked.

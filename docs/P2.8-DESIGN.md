# P2.8 — Read aloud that reads the whole answer, with voice and speed

Item 7 of docs/UI-PHASE2-3-PLAN.md.

## Why

Read aloud stops after 500 characters in Chat and 300 on Home. `/api/tts` writes every result to one shared file,
`~/.codec/pwa_audio.mp3`, so two requests at once can hand one caller the other's audio; it only takes GET, so long
text does not fit in a URL; and its blocking call to Kokoro runs on the dashboard's event loop. Markdown and code
are spoken as written. Settings shows the voice as a raw file path and does not expose `tts_speed` at all.

## What

- **`/api/tts`** (`routes/tts.py`) returns the audio bytes of its own request (no shared file) and runs in the
  thread pool. `POST /api/tts {text, voice?, speed?}` takes up to 1000 characters; the reader sends a sentence or
  two at a time. `voice` must be one of the voices listed below (or the configured one); `speed` must be 0.5-2.0;
  both default to the config (`tts_voice`, `tts_speed`). `GET /api/tts?text=` keeps working (500 characters) for
  old pages.
- **`GET /api/tts/voices`**: the current voice and speed, and the voice list: Kokoro's built-in voices found in the
  local model cache (for example `am_adam`, labelled "Adam, American English, male") and the custom voices in
  `~/.codec/voices/kokoro/` (labelled "Your voice: k2-george-onyx", id = the file path, as `tts_voice` stores it).
- **Reader in the shell** (`CodecShell.speech`): turns the answer into plain speech text (drops code blocks, keeps
  link and image text, removes Markdown marks, table pipes and bare URLs), splits it into sentence-sized pieces,
  fetches the audio of the next two pieces ahead while one plays, and plays them in order on one audio element.
  A small player strip under the top bar (in the page flow) shows "Reading aloud", the piece count, Pause or Resume,
  the speed (0.9x to 1.4x, per device, applied as the audio playback rate so it changes at once) and Stop.
- **Pages**: Chat's Speak button and voice-reply autoplay, and Home's voice replies, use the reader; no length cut.
- **Settings** (Home, Settings, General): a "Voice" section with the voice list (grouped: Your voices, English,
  Other languages), a Preview button that says a 3-second line in the chosen voice, and a speed slider for
  `tts_speed` (0.7-1.3). Both save at once through `PUT /api/config`, which now validates `tts_speed`. The generic
  Text-to-Speech rows stop showing `tts_voice` (it was a raw path box) so the two cannot disagree.

## Not in this item

The live voice call's own voice and speed (codec_voice, P2.9 is the voice-call item).

## API or schema change

`POST /api/tts`, `GET /api/tts/voices`; `GET /api/tts` returns bytes instead of the shared file; `tts_speed` is
validated in `PUT /api/config` and returned by `GET /api/config`. Per-device localStorage key `codec-read-rate`.
No data change; `~/.codec/pwa_audio.mp3` is no longer written.

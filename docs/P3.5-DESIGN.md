# P3.5 — Proactive check-in that speaks only when something matters

Item 10 of docs/UI-PHASE2-3-PLAN.md.

## Why

CODEC notices nothing on its own between requests. The observer overlay (`codec_proactive`, Phase 3.5) only
matches one window-dwell pattern, and its `/api/proactive` endpoints have no page that calls them.

## What

- **One more check inside the heartbeat cycle** (`codec_checkin.run_checkin`, called from
  `codec_heartbeat.heartbeat()`; no new daemon). Default off. Settings in `~/.codec/config.json:checkin`
  (`enabled`, `every_minutes` 30-120, default 45; `active_from`/`active_until`, default 08:00-20:00; `daily_cap`
  1-12, default 4; `speak`; `checklist`, up to 20 lines). Kill switch: the Settings toggle, and
  `CHECKIN_ENABLED=false`.
- **Gates, in order**: on; the interval since the last check-in has passed; inside active hours; the owner is at
  the Mac (keyboard or mouse in the last 10 minutes, the observer's idle signal); no image job holds its lock;
  today's hits are under the cap. Every run past the first two gates is audited (`checkin_run`, metadata only:
  outcome, reason, pattern, counts).
- **Snapshot for the local model only** (never a cloud model: the check-in uses `llm_base_url` only when it is
  local, and skips otherwise): the time; observer metadata (the current app and the apps of the last 10 minutes;
  no window titles, no screen text, no clipboard); calendar events in the next 2 hours; due follow-ups (Daybreak
  waiting-on and follow-up threads); the count of unread important email; failing services (errored CODEC PM2
  apps, services down) in plain words; the owner's checklist.
- **The model answers `NO_REPLY` unless something needs attention**; otherwise one JSON object with a short
  `pattern` slug, a `title`, a `message` and one `spoken` sentence. A hit whose pattern the owner turned off
  ("Never") or dismissed today is dropped.
- **A hit** becomes a `checkin` card on Home (the Today store) with Act (acknowledges through
  `/api/proactive/acknowledge` and opens a new chat with the message as a draft), Snooze (1 hour), Dismiss today
  and Never for this pattern (`/api/proactive/dismiss` with scope today or forever). With speaking on, the one
  sentence is said on the Mac (never during a voice call).
- **Emoji**: heartbeat text that reaches a card is stripped of emoji; the service status words in the heartbeat
  are plain words.
- **Settings** (Home, Settings, General, "Check-ins"): On, every, active hours, daily cap, say one sentence aloud,
  checklist; `GET/PUT /api/checkin`, plus today's count and the last run.

## API or schema change

`GET/PUT /api/checkin`; new config key `checkin`; new audit event `checkin_run`; Today cards of kind `checkin`
(pattern in `source`). The `/api/proactive` endpoints get a caller. No database change.

## Test plan

tests/test_checkin.py: each gate; the snapshot holds the expected parts and no titles, screen text or emoji;
`NO_REPLY` posts nothing and is audited; a hit posts one card, counts toward the cap, is audited, and speaks one
sentence when asked; killed and dismissed-today patterns are dropped; a cloud model is never used; the heartbeat
calls the check-in; the settings route validates; the Home section and card actions are wired to the proactive
endpoints.

Browser (throwaway dashboard): the Settings section saves; a check-in card with its four actions (Act opens a chat
with the draft, Snooze, Dismiss today, Never); 1470x956, 375x812, light theme.

## Rollback

Revert the PR; the `checkin` config key is then ignored.

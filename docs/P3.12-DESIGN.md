# P3.12 — Learning page: review what CODEC proposes to learn

Item 30 of docs/UI-PHASE2-3-PLAN.md. Stacked on P3.11 (#438).

## Why

The self-improvement run (`codec_self_improve`) drafts skill proposals into `~/.codec/skill_proposals/<date>/` and
the only way to accept one is `python3 scripts/promote_skill.py <name>` in a terminal (which copies it into the
repo's hash-pinned `skills/` folder). There is no page that lists the proposals, says which passed the safety check,
or shows what CODEC learned on a given day.

**Found while building this:** the facts that `fact_extract` (and the nightly `auto_memorize`, which runs it) learns
never reach the facts table. `skills/fact_extract.py` calls `CodecMemory().store_fact(fact)`, a method `CodecMemory`
does not have; the `AttributeError` is swallowed, so each fact is kept only as a conversation row (`role="fact"`),
which search finds but nothing can list, edit or forget. On this Mac: 28 such rows, none in the facts table.

## What

A **Learning** page in the Settings group, next to Memory:

- **Proposed skills.** Every proposal from `~/.codec/skill_proposals/`, newest first: name, date, what prompted it
  (gap kind, the tool, how many times), and whether it passed the safety check when it was drafted (and why not).
  **Review** stages its code through the existing `POST /api/skill/review` and shows the code; **Approve and
  install** goes through the existing `POST /api/skill/approve` (built-in-name refusal, AST safety check, written to
  the user skills folder, audited `skill_approved`). **Not now** discards the staged review (`POST
  /api/skill/reject/{id}`); the proposal stays. A proposal that failed its check has no Review button. One already
  installed says so. Nothing installs by itself. The proposal note now says "Settings > Learning" instead of the
  promote script (the script still works).
- **What CODEC learned** — a readable diary for the last 14 days, one entry per day with anything in it: the facts it
  learned (the text), the skills it proposed, and the skills you approved or turned down (from the audit log).
  Built when the page opens; there is no nightly job, so nothing new competes with the image job or the model memory.
- **Recently learned facts.** The active facts `fact_extract` saved, newest first, with **Edit** (a new value; the
  old one stays in the history) and **Forget** (`expire_fact`: closed, kept in the history), through the existing
  Memory page routes. Facts keep saving without any approval, as today.

**The fix the list needs.** `fact_extract` now also stores each fact in the facts table it always meant to use
(`codec_memory_upgrade.store_fact`, key `learned:<10 hex of its SHA-1>`, type `learned`, source `fact_extract`), next
to the conversation row it already writes. The same fact learned twice is one fact. Older learned facts stay where
they are (conversation memory, found by search); the page says how many there are and does not move them. The skill
manifest is regenerated for the changed built-in, as the load-time gate requires.

## API

- `GET /api/learning/proposals` → `{proposals: [{date, name, status: passed | rejected | unknown, reason, gap_kind,
  tool, signals, code, installed}]}` (read-only; names and dates from the folder, code capped at 20,000 characters).
- `GET /api/learning/diary?days=14` → `{days: [{date, facts: [...], proposed: [{name, status}], approved: [...],
  turned_down: [...]}], older_facts: N}`.
- `GET /api/learning/facts` → `{facts: [...]}` (active facts with source `fact_extract`, newest first).

No new write route: Review, Approve, Not now, Edit and Forget use the existing gated routes.

# P3.3 — Schedule any skill, crew or prompt in plain language

Item 8 of docs/UI-PHASE2-3-PLAN.md.

## Why

Tasks > Schedules can only schedule a crew at a clock time on chosen days. A timed fire calls the crew, but
"Run now" takes a different path (a canned LLM report). A fire only leaves a notification; the history is written
only by "Run now", with a 200-character preview. A run missed because the Mac slept across midnight is lost, and a
job enabled at 14:00 for 08:00 fires at once.

## What

**Jobs** (`~/.codec/schedules.json`, additive fields; existing entries keep working as daily crew jobs):
- `kind`: `crew` (crew + topic, as today), `skill` (a skill name + its task) or `prompt` (free text for the local
  model). A scheduled skill must not be destructive (`codec_consent.is_destructive_skill`): such skills keep their
  strict consent and are refused at creation and again at run time.
- `when`: `{"type": "daily", "hour", "minute", "days"}` or `{"type": "every", "minutes"}` (15 minutes to 7 days),
  written in plain language: "weekdays at 7:30", "every 2h", "mondays and thursdays at 9am", "at 18:00",
  "every 30 minutes", "weekends at noon". `describe_when` gives the text back ("Weekdays at 07:30") and parses to
  the same job. Old `hour`/`minute`/`days` fields are read as a daily `when`.
- Options: `deliver` (any of `notification`, `today`, `gdoc`; default notification), `speak` (say the result on
  the Mac with Kokoro, not during a live voice call), `only_if_changed` (deliver nothing when the output equals the
  last run's), `continuity` (the last successful output is given to the next run as context), `label`.

**One runner** for timed fires and "Run now" (`codec_scheduler.run_scheduled`): runs the job, records the run,
then delivers. Timing (`due`): a daily job fires once for its latest due time; a due time earlier today always
counts (as before), one from an earlier day counts for 12 hours (the across-midnight catch-up), and due times before
the job was created or last enabled never count. An `every` job fires when its interval since the last run (or since
it was enabled) has passed, once even if several intervals were missed.

**History** (`~/.codec/schedule_runs.log`, JSON lines, 0600): every run, timed or manual, with the full output (up to
20,000 characters), `changed`, and the Google Doc link. `GET /api/schedules/history` returns parsed entries, newest
first, and still reads the old JSON (`body_preview`) and `|` lines.

**Today cards** (`codec_today.py`, `~/.codec/today.json`, 0600, newest 30): the `today` delivery adds a card; Home
shows the cards above Flash with Show all and Dismiss (`GET /api/today`, `POST /api/today/{id}/dismiss`). The
Morning briefing (P3.1) and the Today home (P3.4) build on this store.

**API** (`routes/schedules.py`): create and update validate every field (update no longer copies arbitrary keys);
`POST /api/schedules/parse {"when"}` returns the reading and the next run for live previews; `GET /api/schedules`
adds `summary` and `next_run`; `GET /api/schedules/skills` lists the skills a job may run.

**UI**: the Tasks > Schedules form asks what to run (Prompt, Skill or Crew), when (plain language, with the reading
and the next run shown as you type), and the options; the list shows the kind, the reading, the next and last run;
History shows each run's full output. In Chat, every reply gets a Schedule action: a small dialog (the shell's
`CodecShell.schedule`) pre-filled with the question that produced the reply, a When field with its preview and the
options, creating an enabled prompt job.

## Not in this item

The voice `scheduler` skill keeps creating crew jobs as before (MCP surface unchanged). Flash replies on Home get no
Schedule action (Flash becomes Today in P3.4).

## API or schema change

Additive job fields; new routes `POST /api/schedules/parse`, `GET /api/schedules/skills`, `GET /api/today`,
`POST /api/today/{id}/dismiss`; history entries gain `output`, `changed`, `doc_url`. New file `~/.codec/today.json`.
